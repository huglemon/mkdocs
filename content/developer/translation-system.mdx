# 内容翻译体系

平台把**全部可翻译内容**统一到一套任务化翻译体系里，目标始终是「**前台启用的每一种语言都产出前台版本**」。

## 后台语言 vs 前台语言（重要）

- **后台录入语言（defaultLocale）**：内容在后台用什么语言录入。
- **前台语言（frontendLocale + 启用列表）**：访客能看到的语言。

两者**解耦**。翻译时以「前台启用的语言列表」为目标：**哪怕录入语言和前台某语言同名，也要产出该前台语言版本**（例如录入是中文、前台也支持 `zh`，仍会重新生成一份前台 `zh` 内容）。所以翻译目录 = 全部启用语言，而不是「除录入语言外的语言」。

## 各实体翻什么

| 实体 | 翻译内容 | 存储 |
|---|---|---|
| **页面 Page** | 标题（默认语言标题 → 目标语言）+ SEO + **全部页面块的文本** | `PageContent` + `PageBlock`（逐语言） |
| **文章 Post** | 标题、摘要、正文（Plate 富文本）+ **SEO（seoJson）** | `PostTranslation.seoJson` |
| **产品 Product** | 标题、摘要、正文 + **SEO（seoJson）** | `ProductTranslation.seoJson` |
| **分类 Category** | 名称 + 描述 | `CategoryTranslation(name, description)` |
| **标签 Tag** | 名称 | `TagTranslation(name)` |

分类/标签的 `name` 主表字段保留为**默认语言录入值**；目标语言译文存翻译表，公开 API 按请求 locale 解析（`slug` 不本地化，URL 跨语言稳定）。

## 页面块：按类型翻译文本

页面翻译会**复制默认语言的全部 active 块**结构，并翻译其中**自然语言文本**（不再「原样复制」）：

| 块类型 | 翻译的字段 |
|---|---|
| `text` | `heading`、`text` |
| `single-image` | `alt`、`caption` |
| `carousel` | 每个 item 的 `alt`、`title` |
| `gallery` | `title` + 每个 item 的 `title` |
| `list` | 每一列的 `label` + 各**文本列**（`text`/`textarea`）单元格 |
| `html` | HTML 文本（**保留标签**） |
| `json` | 递归翻译其中像自然语言的字符串（跳过 URL / 纯数字） |
| `post-list` / `product-list` / `group` / `form` | 不含用户文本：仅复制结构/配置 |

> 列表列类型为 `image`/`link`/`icon`/`number` 的单元格**不翻译**（不是自然语言）；配置类字段（limit/categoryIds/表单 slug）跨语言共享。

## SEO 翻哪些字段

`SeoJson` 里**只有自然语言字段**参与翻译：

```text
metaTitle / metaDescription / keywords[] / ogTitle / ogDescription
```

`ogImage` / `canonical` / `ogType` / `robots` / `jsonLd` 等（URL、枚举、结构化数据）**不翻译**，按源值保留。`keywords` 是**数组**，等长逐项翻译。

## 块级回退与 slug 稳定

- `PageBlock.slug` 是**跨语言回退的稳定身份**：目标语言缺某 slug 时，该块回退默认语言；动态列表块始终按当前 URL 语言查询 API。
- 因此翻译**结构完整**（不会因少翻一块而缺版式），细节见「页面块调用与渲染」。

## 任务化：进度、可离开、幂等

翻译走 `AiTask`（数据库租约 + 心跳防双执行）：

- 后台每个内容类型的操作里点「**翻译到所有语言**」→ **确认框** → 生成后台任务并**立即返回**；
- 页面显示**进度条**，**可离开页面**，任务在 Worker 里继续；
- 终态如实记录：`completed` / `partial`（部分成功）/ `failed`，并区分 **保存 / 跳过 / 失败 / 缺失** 计数。

**手动保护（文章/产品）**：标记为 `source = manual` 的翻译不会被自动覆盖；需要覆盖时用「**全部重翻（含手动）**」。

## 完整性判定与「再翻一次即补翻」

翻译前会校验目标是否**完整**（标题、SEO、块文本、正文节点路径逐一比对）：

- 已完整 → 标记 `skipped`（幂等，不重复消耗）；
- 不完整（例如历史遗留、早期版本漏翻的块或 SEO）→ 重新翻译并补齐。

> 这意味着**改进了翻译实现后，对既有内容再点一次「翻译到所有语言」即可自动补翻**漏掉的部分，无需迁移脚本。

## 新项目开发怎么用

- 翻译体系完全在**后台 + 模板基线**里，新分支**不需要任何改动**。
- 模板只需按 `locale` 取数（`getPage` / `getPosts` / `getProducts` / `getCategoryTree(type, locale)`）——`main` 已内置。
- 分类/标签的**本地化名称**由 API 按 `locale` 返回（见「公开 API 参考」），模板侧栏无需处理。
