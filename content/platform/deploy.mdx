# 部署与域名

## Vercel 部署

- 建站勾选「同时创建 Vercel 部署」→ 自动创建 Vercel 项目 + 注入 env + 触发构建
- 站点详情页「部署状态」查看进度，READY 后获得预览域名
- 新项目**默认不连接 Git**：push 不会自动上线，生产由后台「用此分支重新部署」触发（见「部署隔离」）

注入 env：ADMIN_API_URL、SITE_ID、SITE_SECRET、REVALIDATE_SECRET、NEXT_PUBLIC 系列（语言/Umami/取数）。

## 部署隔离（重要）

每个客户站点独占一个 `client-xxx` 分支和一个 `site-client-xxx` Vercel 项目。正式发布**只能**来自「本项目 + 客户分支」，绝不会因为分支名相同而覆盖其他站点。

**两种上线方式（二选一）**

| 方式 | push 自动上线 | 人工前置 |
| --- | --- | --- |
| 显式部署（默认） | ❌ 不部署 | 无；后台点「用此分支重新部署」 |
| 连接 Git 自动部署 | ✅ push 客户分支即上线 | 建站后到 Vercel 面板手动连接并选对分支 |

后台「部署状态」会标出当前状态：

- 灰「未连接」——push 不会自动上线，生产只能由后台显式部署
- 绿「已连接，分支 client-xxx」——push 该分支自动上线
- 橙「生产分支绑错：实际 main ≠ 期望 client-xxx，已自动断开」——守卫已断开其自动部署

**关键约束：连接 Git 时，生产分支必须等于该站客户分支。**

生产分支的真身是 Production 环境的 `branchMatcher`（`{ type: "equals", pattern: "main" }`）。**连接仓库这一步可由 API 自动化，分支却不能**——实测结论：

| 尝试 | 结果 |
| --- | --- |
| `POST /v9/projects/{id}/link` 带 `productionBranch` / `branch` | 200，但字段被**静默忽略** |
| `PATCH /v9/projects/{id}` 带 `productionBranch` / `branchMatcher` / `systemEnvironments` | **400**（拒绝未知字段） |
| `PATCH` / `PUT` `/v9/projects/{id}/environments[/production]` | **404** |
| `GET /v9/projects/{id}/environments` | ✅ 200，**只读** |

所以：**不自动化 connect**——自动连接只会得到绑在 `main` 的项目，随后就被守卫断开，毫无意义。连接与分支必须**成对人工完成**。绑成 `main` 会让模板 `main` 一推送就误覆盖该客户站，这是真实发生过的故障。

> 连接仓库这一步**只选仓库、不选分支**，连接后生产分支默认为 `main`；分支要在 **Settings → Environments → Production → Branch Tracking** 里单独修改（见下方步骤）。

**自动守卫（fail-safe）**

- **部署前**：发现项目已连 Git 且生产分支 ≠ 该站客户分支 → 立即调用官方接口断开其自动部署。
- **每 10 分钟**：AI Worker 全站审计同一规则，绑错即断开并记录日志。
- 因此误绑最多影响一个审计周期（≤10 分钟），随后自动停止自动部署；修正后需人工重新连接。

> 若 AI Worker 未运行，定时审计不会执行——只部署 CMS 而不重启 Worker 时，守卫只剩「部署前」这一道。

### 给某站开启「push 自动上线」

1. 确认 **AI Worker 已重启**（定时审计跑在 Worker 里，未重启则守卫未武装）。
2. Vercel 面板打开该站项目 → **Settings → Git → Connect Git Repository**，选择模板仓库并连接。
   > 此步**只能选仓库，不能选分支**；连接后生产分支按 `main` → `master` → 仓库默认分支的顺序自动选中，实际就是 `main`。
3. 切到 **Settings → Environments → Production → Branch Tracking**，把分支名改为 `client-{站点}` 并 **Save**。
   （例：项目 `site-client-yimu-charcoal` → 分支 `client-yimu-charcoal`）
   > 第 2 步完成到第 3 步保存之间，生产分支是 `main`——这段时间若有 `main` 推送，会被当成该客户站的生产发布。请尽快完成第 3 步；守卫会在发现不一致时断开，但最多滞后一个审计周期。
4. 回后台站点详情看「部署状态」那行是否**变绿**；橙色代表绑错，守卫会把自动部署断开。
5. 之后 push 该客户分支即自动上生产。

> 模板仓库 `main` 只是基线，不对应任何客户站；各站内容各自维护在 `client-xxx` 分支。

## 构建性能与区域（重要）

客户站点的构建时间 ≈ 预渲染页数 × 每页取数调用 × 单次调用延迟。我们用三件事把它压下来：

- **函数区域固定香港 `hkg1`**：CMS 与模板都通过 `vercel.json` 的 `"regions": ["hkg1"]` 与自建 PostgreSQL（香港）**同区**。此前二者跑在 Vercel 默认美东 `iad1`，每次查询跨太平洋往返——同区后单次调用延迟降一个数量级，**典型客户站点构建从 ~8 分钟降到 ~1.5 分钟**（线上请求一并受益）。
  > 新建站点若缺 `vercel.json`，需在 Vercel 项目设置里把 Region 设为 **Hong Kong (hkg1)**。
- **预渲染上限按类型拆分**：`STATIC_PRERENDER_PRODUCTS_LIMIT`（默认 50）、`STATIC_PRERENDER_NEWS_LIMIT`（默认 20），超出的走按需 ISR——构建时间**不随内容量增长**，只与「预渲染页数」相关。
- **页面全量预渲染**：后台「页面管理」里的**所有已发布页面**都在构建期预渲染（页面数量少，× 语言也无压力），保证首页 / 导航目标 / 广告落地页「一点即达」。

> 冷启动说明：未被预渲染的长尾页（产品/文章超出上限者）走 **ISR**——第一个访问者触发一次服务端渲染并缓存，之后与预渲染无异。所以面向转化的关键页务必是「页面管理」中的**已发布页面**。

## 自定义域名

「域名管理」→ 输入域名 →「添加」：
1. 绑定：Vercel 项目绑定域名（已在 Vercel 绑定则自动接管）
2. DNS 验证：显示验证记录（TXT/CNAME），去域名服务商配置
3. 验证：配置 DNS 后点「验证」，通过则启用
4. SSL：验证通过后 Vercel 自动签发证书

域名托管在 Cloudflare 时，在 Cloudflare 加对应 DNS 记录指向 Vercel。

## 移除域名

删除域名后回退到预览域名（vercel.app 别名），正式域名清除。
